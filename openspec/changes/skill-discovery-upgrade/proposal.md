# Proposal: Skill Discovery Auto-Detect Upgrade
Generated by: cm-brainstorm-idea
Date: 2026-04-18

## Why we're doing this
### Qualified Problem
**For:** AI Agents operating in CodyMaster workloads  
**Who:** currently spend tokens, execution time, and guess-work attempting to identify which community skills to fetch.  
**The:** skill discovery process is a static LLM-driven lookup against `cm-skill-index`  
**That:** needs to become an automatic, deterministic, zero-token parsing layer.  
**Unlike:** the manual lookup and "fire and forget" guesswork that occasionally results in bloated `skills` folders or missing dependencies.  
**Our approach:** Learn from `midudev/autoskills` to statically parse config files (`package.json`, `go.mod`, etc.) and inject a slimmed-down tech-specific context.

## What's changing
### Options Evaluated
1. **Option A: The "Pre-flight Auto-scan Engine"**: Direct port of `autoskills` to automatically mass-download skills into `.agents/skills`. Very fast, but potentially pollutes the workspace with skills the LLM doesn't actively need for the current task.
2. **Option B: The "Skill Index Compiler"**: Extract the deterministic AST-scanning logic of `autoskills` but use it to compile a dynamic `AGENTS.md` injected token-light context summary that points to exactly 3-4 specialized skills. The LLM still initiates the download.
3. **Option C: Direct Passthrough Integration**: Silently invoke the 3rd-party `npx autoskills` bin at project bootstrap without rewriting it. We lose control over format, but requires zero maintenance.

### Recommendation
**Choose Option B: The "Skill Index Compiler"**

**Why this option:**
1. Preserves the AI's agency to load skills through Progressive Disclosure (Layer 3), enforcing token efficiency while dropping the massive Layer 1 size constraint.
2. We retain full control over the file paths, enforcing `.gemini/antigravity/` routing which `autoskills` doesn’t natively understand.
3. Avoids "install clutter"—the LLM only runs `npx skills add` when necessary, but it operates with 100% precision because it knows exactly what the stack is.
