# Proposal: Defer to Host Browser, Restore cm-ux-master, Trim Redundant Skills

Generated by: cm-brainstorm-idea
Date: 2026-06-11
Decision: Option B — Consolidation (balanced) · Skill cuts: Moderate (~45 skills)
Canonical source (per maintainer): https://github.com/tody-agent/codymaster

## Why we're doing this

### Qualified Problem

**For:** CodyMaster maintainers and the agents/users who run the kit across Claude Code, Google Antigravity, Codex, and Cursor
**Who:** need a kit that is lean and trustworthy, and that leverages each host platform's native capabilities instead of re-implementing them
**The:** current kit (61 skills) ships its own Playwright browser daemon (`cm-browse`) and proactively drives it
**That:** is now redundant and inferior to the host platforms' built-in browser modes/agents (Claude in Chrome, Claude Preview, Antigravity/Cursor/Codex browser mode), carries one corrupted core skill (`cm-ux-master`), and is bloated with deprecated/duplicate/micro skills
**Unlike:** a self-contained kit that owns every capability, CodyMaster wins by staying small and delegating browser + specialist work to the host
**Our approach:** demote the in-house browser to a CLI-only fallback, restore + harden `cm-ux-master`, and consolidate the skill catalog to ~45 focused skills

### Discovery Evidence (Phase 1 audit)

- **Two divergent versions exist.** Dev repo (this working tree) = **v6.0.0**, 61 skills. Live marketplace install (`…/marketplaces/local-desktop-app-uploads/cm`) = **v7.0.2**, ~50 skills, already deprecates `cm-design-studio`/`cm-test-gate`. The marketplace is **not** a symlink and **not** in this repo's git.
- **Remote is broken.** `origin` = `git@github-personal:tody-agent/cm-plugin.git` (note: `cm-plugin`, not `codymaster`); `git fetch` returns "Repository not found". Cached `origin/main` tops out at **v5.1–5.2**. No v7 exists anywhere in local git — the live v7 was built from a source not visible here.
- **Browser is driven proactively.** `cm-browse` says *"Before claiming 'UI works', drive `cm browse` + `cm qa-visual`"*; `cm-engineering-meta:68` routes *"Test the website" → `cm browse + cm qa-visual`*. Also wired into `cm-qa-visual-cli`, `cm-post-deploy-canary`, `cm-safe-deploy` Gate 6, `cm-mcp-engineering` (`cm_qa`), and agent `ux-designer.md:48`. The plugin **never references** host browser-native tooling.
- **cm-ux-master is corrupted.** `skills/cm-ux-master/SKILL.md` contains `cm-continuity` content (wrong `name:` + body, 173 lines vs ~577). All other assets (`cli/`, `mcp/`, `references/` = 48 UX Laws + 37 design tests, `data/` = BM25 1032 rules, `templates/`) are intact. A clean SKILL.md exists at git `280c182`. Corruption was introduced by commit `ad033ee "audit & repair all 33 skills"` — i.e. by the kit's own auto-repair tooling.
- **Catalog bloat.** 3 deprecated (`cm-design-studio`, `cm-test-gate`, `cm-terminal`); 12 micro-skills (<35 lines); duplicate clusters (status+dashboard, 2× worktree, 7× skill-meta, design ×4, gate ×5).

### Root Cause(s)

1. **Timing debt:** the Playwright daemon predates host browser modes; it was correct in 2024-era CLI-only contexts but is now redundant where the host has a browser.
2. **Unsafe automation:** `cm-skill-evolution` / `skill-evolver.ts` auto-repair can overwrite a skill's `SKILL.md` with the wrong content (no name-match guard) — this clobbered `cm-ux-master`.
3. **No consolidation policy:** skills were added faster than overlaps were merged; deprecation isn't signalled in frontmatter.

### Impact if NOT addressed

- **User:** agents waste tokens/time starting a local daemon when the host already has a better browser; "test the website" routes to the wrong tool.
- **Product:** a flagship design skill (`cm-ux-master`) is dead; discovery is noisy across 61 skills.
- **Tech:** the same auto-repair bug can corrupt other skills again at any time.

## What's changing

### Options Evaluated

- **Option A — Surgical:** restore ux-master + one note on cm-browse + delete 3 deprecated. Score 6.0. Rejected: leaves browser proactive everywhere and the auto-repair bug unfixed.
- **Option B — Consolidation (CHOSEN):** centralize a host-first browser policy + demote daemon to fallback; restore + optimize + harden ux-master; trim to ~45 skills. Score 7.95.
- **Option C — Full v7 alignment:** B + reconcile v6↔v7 + cut niche verticals to ~35. Score 6.75. Rejected for now: high risk, touches the "60+ skills" positioning, needs full regression.

### Workstream 1 — Browser: defer to host, daemon as fallback

- New shared policy `skills/_shared/browser-strategy.md` defining detection order:
  1. **Host browser-native first** — Claude Code (`Claude in Chrome`, `Claude Preview` MCP), Antigravity / Cursor / Codex browser mode.
  2. **Fallback only on bare CLI without browser mode** — then *suggest* `cm browse` to the user; do **not** auto-launch.
- Edit proactive call sites to consult the policy and stop auto-driving the daemon:
  - `cm-browse` (reframe as fallback; remove "always drive before claiming UI works")
  - `cm-engineering-meta:68` (route "test the website" → host browser first)
  - `cm-qa-visual-cli`, `cm-post-deploy-canary`, `cm-safe-deploy` Gate 6, `cm-mcp-engineering` (`cm_qa`), `agents/ux-designer.md:48`
- Update `docs/browse-daemon.md` + ADR `docs/adr/001-playwright-browse-daemon.md` to record the host-first decision.

### Workstream 2 — Restore + optimize + harden cm-ux-master

- **Restore:** `git show 280c182:skills/cm-ux-master/SKILL.md > skills/cm-ux-master/SKILL.md`; verify `name: cm-ux-master` and ~577 lines.
- **Optimize:** trim to progressive-disclosure (lean SKILL.md → references on demand); make delegation explicit (ux-master = wisdom layer → `cm-design-system` extraction → `cm-ui-preview` Stitch); switch its internal Playwright harvest to honor the Workstream 1 host-first policy.
- **Harden (reliability):** add a name-match guard + `.md` backup-before-write to `cm-skill-evolution` / `src/skill-evolver.ts` so auto-repair can never write skill B's content into skill A again. Add a `cm-skill-health` check: folder name must equal frontmatter `name:`.

### Workstream 3 — Trim to ~45 skills (Moderate)

Each **delete** requires per-skill confirmation at execution (look at the file before removing). Proposed set:
- **Delete (deprecated):** `cm-design-studio`, `cm-test-gate`, `cm-terminal`.
- **Merge duplicates:** `cm-dashboard` → `cm-status`; `cm-conductor-worktrees` → `cm-git-worktrees`; `cm-qa-visual-cli` → `cm-browse`; `cm-post-deploy-canary` → `cm-safe-deploy` (Gate 6); `cm-skill-search` → `cm-skill-mastery`; `cm-skill-health` → `cm-skill-evolution`.
- **Demote/move (not user-facing skills):** `cm-example` → `templates/`; `cm-ecosystem-roadmap` → `docs/`.
- **Keep all niche verticals** (google-form, booking-calendar, ads-tracker, readit, notebooklm, growth-hacking, cro-methodology, jtbd) — out of scope for Moderate.
- Net: 61 → ~45–47. Update `marketplace.json` skill lists, `cm-skill-index`, and any cross-references after each removal.
