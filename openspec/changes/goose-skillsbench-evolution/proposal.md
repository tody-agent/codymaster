## Why we're doing this

### Qualified Problem

**For:** AI developers using Claude Code, Cursor, Goose để code
**Who:** Cần chứng minh ROI khi adopt CodyMaster vào workflow
**The:** CodyMaster v5.0.0 là powerful AI orchestration layer với Smart Spine, MCP, 56 skills
**That:** Thiếu 3 thứ để được adopt rộng rãi:
  1. **PROOF** — không có số đo cụ thể về "CodyMaster helps"
  2. **REACH** — chưa tích hợp với Goose (55K users) hay ecosystem rộng hơn
  3. **EFFICIENCY** — skill loading vẫn static, chưa apply SkillsBench findings
**Unlike:** Goose (55K users, transparent benchmarks, 373+ contributors)
**Our gap:** Infrastructure đã xong (v5.0 Smart Spine), nhưng thiếu proof + reach + efficiency

### Research Sources
- **Goose analysis**: Rust architecture, MCP ecosystem, benchmark framework (`goose-bench`), custom distributions, memory extension, declarative providers
- **SkillsBench** (peer-reviewed): 86 tasks, 11 domains, 7,308 trajectories
  - Curated skills: +16.2pp improvement average
  - Self-generated skills: -1.3pp (harmful)
  - 2-3 focused skills: **+18.6pp** vs 4+ skills: +5.9pp
  - Monolithic skills: -2.9pp (actively harmful)
  - Average public skill quality: 6.2/12 — only top quartile (9+/12) creates real improvement

### Root Causes
1. **Proof gap** — No benchmark comparing with/without CodyMaster → credibility = 0 with new users
2. **Reach gap** — MCP server exists but not packaged for Goose/community → ecosystem isolated
3. **Efficiency gap** — SkillsBench: 2-3 focused skills = +18.6pp. Current chains load 3-6 statically. No dynamic per-task selection.

### Impact if NOT addressed
- **Credibility**: No adoption without proof. Goose published benchmarks with 8 tasks — CodyMaster has 0.
- **Ecosystem isolation**: 55K Goose users unreachable. CodyMaster stays a solo/niche tool.
- **Performance decay**: As skill count grows (56→80+), static loading degrades vs dynamic 2-3 selection.

## Recommendation: Option C — Parallel Sprints

Execute 5 independent actions in 2 weeks. Infrastructure (v5.0) is already ready — these are extensions, not rebuilds.

### Why Option C:
1. **v5.0 infrastructure is complete** — Smart Spine, MCP, Token Budget already built. 5 actions only extend existing code.
2. **All 5 actions are independent** — can run in parallel. Action 1 is a 1-file edit. Action 4 is ~20 lines. No blockers.
3. **SkillsBench directly applicable now** — Action 1 (limit to 2-3 skills) is smallest change with highest impact per research.
4. **Don't need proof to start growing** — `cm mcp-serve` packaging ships immediately. CodyBench builds credibility in parallel.

### Why NOT A or B:
- **A only**: Build benchmark without growing reach = credibility without audience.
- **B only**: Grow without proof = risky exposure. Goose community will ask "what's the benchmark?" with no answer.

## Implementation Plan: 5 Parallel Actions

### Action 1 — Intelligent Skill Selection (Priority: CRITICAL)
**Files:** `src/skill-chain.ts`, `src/chains/builtin.ts`
**Change:** Add dynamic skill selection limiting to max 2-3 per task using BM25 score ranking.
- Modify chain matching to score each step against task description
- Return top-3 relevant steps instead of full chain
- Add warning when user explicitly requests >3 skills
**Why:** SkillsBench: 2-3 focused skills = +18.6pp vs 4+ skills = +5.9pp. Direct performance win.

### Action 2 — `cm mcp-serve` Command (Priority: HIGH)
**Files:** `src/cli/command-registry.ts` or `src/cli/commands/system.ts`
**Change:** Expose `cm mcp-serve` as a standalone CLI command that spawns `mcp-context-server.ts`.
- Parse `--project`, `--port` args
- Print Goose-compatible config snippet on first run
- Add to `cm help` output
**Why:** MCP server exists but has no user-facing command. One command unlocks Goose integration for 55K users.

### Action 3 — CodyBench v0.1 (Priority: HIGH)
**Files:** New `codybench/` directory
**Structure:**
```
codybench/
├── config.json           # eval config (3 suites, 1 platform)
├── suites/
│   ├── tdd-regression.ts # Does TDD skill catch regressions?
│   ├── token-efficiency.ts # Token savings with/without CM
│   └── memory-retention.ts # Memory accuracy across sessions
├── runners/
│   └── claude-code.ts    # Claude Code runner
└── reports/
    └── leaderboard.json  # Output
```
**Why:** Goose published benchmarks with 8 simple tasks and gained credibility. Start small, publish transparently.

### Action 4 — NLI Trigger Words in MCP (Priority: MEDIUM)
**Files:** `src/mcp-context-server.ts`
**Change:** Add natural language interface layer — ~20 lines mapping trigger patterns to existing tools.
```typescript
// In message handler, before tool dispatch:
if (text.match(/\bremember that\b/i)) → cm_memory_write (TTL = session)
if (text.match(/\bforget about\b/i))  → cm_memory_decay (TTL = 0)
if (text.match(/\bwhat did we learn\b/i)) → cm_query + cm_search
```
**Why:** Goose Memory uses natural language. CodyMaster's 5-tier architecture is powerful but UX requires knowing file structure. NLI removes this friction.

### Action 5 — Community Launch (Priority: MEDIUM)
**Non-code deliverables:**
- Discord server: 3 initial channels (general, skill-dev, show-and-tell)
- GitHub README: add Discord badge + "How to use with Goose" section
- Issue templates: `good-first-skill`, `benchmark-needed`, `skill-improvement`
- Write 1-page "How to use CodyMaster with Goose" tutorial
**Why:** Goose reached 373+ contributors via community programs. CodyMaster needs the same flywheel.
