# Proposal: Self-Healing Skill Recovery
Generated by: cm-brainstorm-idea
Date: 2026-04-17

## Why we're doing this
### Qualified Problem

**For:** CodyMaster users who rely on the published skill catalog and changelog
**Who:** expect advertised self-healing and recovery capabilities to exist and be callable
**The:** current CodyMaster release is a skill-driven engineering workspace
**That:** has drifted between changelog/README promises and the actual bundled skill surface
**Unlike:** a trustworthy release where docs, registry, and shipped skills agree
**Our approach:** recover the missing self-healing surface with minimal-risk implementations that reuse current repo primitives and make the shipped catalog truthful again.

### Root Cause(s)
1. Documentation and changelog claims advanced faster than committed implementation for the self-healing skill family.
2. Existing repo capabilities for discovery, memory, retro capture, and chain selection were not composed into dedicated recoverable skill packs.
3. Skill library docs and discoverability surfaces no longer reflect the public feature story from v4.4.3+.

### Impact if NOT addressed
- Business impact: trust erosion between website/changelog promises and installed product behavior.
- User impact: missing or misleading skill calls (`cm-skill-health`, `cm-skill-evolution`, `cm-skill-search`, `cm-skill-share`).
- Technical debt impact: more hidden drift between docs, packaged skills, and command surfaces over time.

## What's changing
### Options Evaluated

#### Option A: Docs-only rollback
- Remove or soften all references to the missing self-healing family.
- Low implementation risk, but fails the user's request to restore missing functionality.

#### Option B: Full historical resurrection via branches/commits
- Attempt to recover the missing family from GitHub branches or older commits.
- Rejected because GitHub and local history show no committed implementation for these skills, only references.

#### Option C: Minimal viable recovery on top of existing primitives
- Add real `skills/cm-skill-health`, `cm-skill-evolution`, `cm-skill-search`, and `cm-skill-share` packs.
- Reuse current repo building blocks: retro logs, suggestions, SQLite/context memory, skill index/docs, and packaged assets.
- Update discovery/docs so the recovered surface is visible and coherent.

### Recommendation

Choose **Option C: Minimal viable recovery on top of existing primitives**.
