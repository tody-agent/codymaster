# Brainstorm Output: Clean Code + Push Hygiene

Generated by: cm-brainstorm-idea  
Date: 2026-04-10

## Qualified problem

Current repo already has secret scanning, but push hygiene is still incomplete:

- Origin remote URL currently contains embedded GitHub token.
- No dedicated guard for non-main, noisy, or sensitive files before push.
- Existing security scripts are useful but scattered across deploy scripts, making maintenance harder.

### Root causes

1. Secret checks focus on file content, not git remote credential hygiene.
2. No centralized check for tracked garbage files (logs, temp artifacts, private key extensions).
3. Push/deploy pipeline does not enforce one explicit "repo hygiene" gate.

### Impact if not addressed

- High risk of token leakage to shell history/screenshots/shared logs.
- Risk of accidentally pushing unnecessary/sensitive files.
- Maintenance burden when multiple scripts overlap without a clear gate order.

## Options evaluated

### Option A: Keep existing scripts, manual checklist
- Effort: S
- Pros: No code changes
- Cons: Human error prone, no hard-stop for remote token/file noise

### Option B: Add dedicated hygiene gate and wire into deploy (Recommended)
- Effort: M
- Pros: Strong automation, maintainable separation of concerns, immediate risk reduction
- Cons: Slightly stricter workflow

### Option C: Full hook framework (husky/lint-staged + custom hooks)
- Effort: M/L
- Pros: Strong local safeguards
- Cons: More moving parts, bigger rollout than needed now

## Recommendation

Choose **Option B** now:

1. Add `gate:hygiene` script for remote URL and tracked file hygiene checks.
2. Integrate this gate into `deploy` and `deploy:dry`.
3. Keep existing secret/content gate as-is for defense in depth.
